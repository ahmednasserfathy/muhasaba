# 00 | قرارات المنتج والتنفيذ (v1.4)

## الهدف

تطبيق محاسبة يومية عربي مستقل وسهل الاستخدام: متابعة عبادات اليوم، فتح أذكار مفصلة وتسجيل كل ذكر، صيام أسبوعي واختياري ورمضان، تذكيرات، إحصائيات، وحسابات يمكن أن تكون محلية أو مرتبطة بمصدر مستخدمين آخر في المستقبل.

## ما تأكد من الصور والفيديو

- صفحة جدول فيها ثمانية أقسام و34 بطاقة، تاريخ ونسبة تقدم وألوان أحمر/أخضر حسب حالة الإنجاز. الأرقام الصغيرة على بطاقات الجدول تتوافق *استدلالياً* مع نقاط موزونة مجموعها 74 في الخميس المرجعي.
- صورة `385743.jpg`: الضغط على رمز المساعدة يفتح نافذة «المسجد دخول و خروج»، فيها ذكر مُنجز باللون الأخضر والعداد `1/1` وذكر آخر غير منجز باللون الداكن `0/1`. تظهر عبارة `(1 مرة)`.
- صورة `385745.jpg`: نافذة «لبس الثوب و خلعه» بها عدة بطاقات نصية قابلة للتمرير عموديًا، لكل بطاقة عداد مستقل وتكرار مستهدف.
- صورة `385744.jpg`: بعض بطاقات «أذكار متنوعة» عليها علامة `?` وألوان مختلفة تدل على حالة القسم، والنقاط تظهر على البطاقة الرئيسية.
- **غير مثبت:** أن كل مجموعة تعطي نقطتين بغض النظر عن الأذكار، أو كيف تحسب النقاط الجزئية، أو محتوى جميع الأذكار، أو وجود API عام للموقع. سنستخدم سياسة داخلية محددة ومختبرة.

## متطلبات مؤكدة من صاحب المشروع

1. Backend Python ليس NestJS.
2. مجموعة الأذكار تعرض النصوص والعدادات وتسمح بتعليم كل عنصر على حدة.
3. فيديوهات/مراجع مرتبطة من مصادر رسمية إذا كانت واجهات الاستخدام متاحة ومصرح بها.
4. إشعارات وتذكيرات.
5. صيام الاثنين والخميس كافتراضي، مع إمكانية إضافة أي يوم، ورمضان كنظام موسمي.
6. قابلية استيراد/ربط مستخدمين من DB مختلفة مستقبلًا وتمييز مصدر إنشاء الحساب.
7. تطبيق احترافي من غير Overengineering.

## Scope واقعي

**MVP core:** حساب محلي، Catalog، شاشة يومية، تفاصيل الأذكار، صيام مرن، حفظ Offline، API Python + PostgreSQL، تقارير بسيطة، تذكيرات محلية، إدخال محتوى أذكار موثّق، وصلاحيات وصول.

**Extension-ready but deferred:** الربط الفعلي بقاعدة مستخدمين خارجية، واجهة إدارة محتوى رسومية متقدمة، Push server notifications، حساب مواقيت الصلاة، تشغيل فيديوهات داخل التطبيق، مزامنة متزامنة معقدة بين أجهزة متعددة، تصدير PDF، إشعارات مرتبطة بالموقع، social/gamification.

**No-go:** نسخ الحسابات الأصلية أو شعار الموقع، scraping غير مصرح، تخزين أسباب الاستثناءات الصحية، وادعاء تطابق القواعد التي لم تظهر لنا.

## Simple stack

| Part | Decision |
|---|---|
| App | Flutter + Riverpod + go_router |
| Local DB | SQLite/Drift |
| HTTP | Dio |
| API | Python/FastAPI with Pydantic |
| Domain/DB | SQLAlchemy 2, Alembic, PostgreSQL |
| Test | pytest (API), Flutter test (mobile) |
| Quality | Ruff, flutter analyze, CI |
| Notification | flutter_local_notifications, time-zone-aware on device |
| Infra | Docker Compose local, single FastAPI service in production initially |

## Product principle

**Daily journal is the core.** A content library and future integration shall not be prerequisites for the journal to function. First PRs establish domain and schema, then a complete vertical user flow, then reminders and optional resources.

## تعديل v1.2 المعتمد من صاحب المشروع (20 نوفمبر 2026)

- كل ذكر مكتمل أو جزء من تكراراته يرفع النقاط فورًا، ولا ننتظر اكتمال المجموعة.
- توزيع النقاط المقترح: وزن المجموعة × متوسط نسب إنجاز أذكارها. كل ذكر له حصة متساوية، والتكرارات تحسب داخل الذكر.
- تظهر حالة PARTIAL مع النقاط الحالية والباقي ونصيحة إيجابية قصيرة دون لوم.
- إشعار اختياري لطيف بالأعمال المؤهلة المتبقية، بحد أقصى مرة في اليوم وفي وقت يحدده المستخدم، ويُلغى/يُعاد جدولته بعد تحديثات الجهاز المحلية.
- لا حاجة لأي خدمة إرسال Push أو Background Queue في MVP.

## تعديل v1.3 المعتمد: قابلية التراجع والتخصيص

- النقر على نشاط ثنائي مثل صلاة الظهر **يتبدل** بين مكتمل وغير مكتمل، مع إلغاء العلامة وتصحيح النقاط فورًا. يُسمح بتعديل اليوم الحالي والأيام السابقة ضمن تاريخ الحساب؛ يمنع تسجيل إكمال يوم مستقبلي فقط. لا نفرض قيدًا على الساعة الفعلية للصلاة دون خدمة مواقيت موثوقة؛ يمكن إضافة تحذير لطيف لاحقًا.
- إدخال أذكار مجموعة تفصيلية قابل للزيادة والنقصان، وكل تغيير يعيد حساب الجزء المكتسب فورًا.
- المكتبة **الرسمية** مركزية تحت إدارة ADMIN فقط، والمستخدم لا يحررها أو يحذفها. خيارات المستخدم «إخفاء من خطتي / استعادة» لا تزيل العنصر من المكتبة العامة.
- المستخدم يكتب أدعيته وأذكاره **الشخصية والخاصة**، ويربطها بمجموعة موجودة، مثل أذكار الصباح. يستطيع إخفاء بعض عناصر المجموعة الافتراضية، إضافة عناصره، ترتيبها وضبط عداد التكرار.
- **تصحيح v1.4 المعتمد:** الـ Score يُحتسب فقط من وزن الكارت الرئيسي ومن الأذكار الرسمية المعتمدة المرتبطة به. إضافات المستخدم الشخصية، إخفاء ذكر افتراضي من الواجهة، أو إعادة ترتيبه لا تؤثر على النقاط المكتسبة أو إجمالي الممكن. الإخفاء للعرض فقط ولا يعني الإنجاز أو الإعفاء. يحتفظ النظام بالتاريخ دون إعادة حساب.
- إضافة Admin CRUD بسيط للمكتبة وعملية مراجعة/نشر بإصدارات، بدون لوحة CMS ضخمة. الإضافة الشخصية لا تُنشر لباقي المستخدمين ولا تُعامل كمحتوى ديني موثق.
- سجل خطط المستخدم وإصدارات المحتوى يحمي التاريخ بدون Event Sourcing أو ميكروسيرفيسز.

## Locked MVP v1.4, supersedes v1.3 personalization scoring

- Main activity cards only establish score weights. Official score-eligible nested adhkar split a parent card's weight proportionally; partial progress counts immediately.
- Personal custom items have independent progress and reminders (if enabled) but **zero score contribution**. Hiding/reordering official items is UI-only and does not recompute their scoring eligibility. User can restore/show hidden score-bearing items to understand what remains.
- Single modular Python FastAPI backend, PostgreSQL and Flutter offline-first. No extra services for future ideas.
- See `10_LOCKED_CORE_MVP_AR.md` for precise behavior, acceptance cases, and Codex boundaries.
